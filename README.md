# AI 文献核验器（ai-lit-checker）

> 当前版本：v1.0.0 ｜ [在线试用](https://hanmochunqiu1512.github.io/ai-lit-checker/) ｜ [Releases](https://github.com/HanmoChunqiu1512/ai-lit-checker/releases)

把 AI 生成的一段参考文献粘进来，逐条核验真伪，并把人机分工写进流程里。

自动层查 Crossref（有 DOI 直接验 DOI），人工层比对图书馆导出的题录，中文条目用浏览器插件按「篇名」去知网批量检索，结果回填到同一个表格里，最后一键导出 CSV / 打印报告。

> 面向场景：AI 写论文、写综述时编造参考文献；学生、编辑、科研助理需要一条能复现的核验流程。

---

## 它解决什么问题

AI 生成的参考文献有三个典型病灶：

1. **整条编造**——题名、作者、期刊看着都很像，实际不存在；
2. **半真半假**——文献真实存在，但年份、卷期、DOI 对不上；
3. **DOI 幻觉**——给了一个格式完美却解析不了的 DOI。

现有研究多是「测一批、报个数字」，缺少可复用的核验流程与工具。本项目把流程固化成工具：
**自动初筛 + 一键人工复核 + 结果可导出**。

## 三种用法

### 1）网页版（最简单，单文件）

直接用浏览器打开 `web/index.html`，或部署到 GitHub Pages（见下文）。

- 粘一段参考文献 → 开始核验
- 有 DOI 的条目查 Crossref；DOI 无效直接判「虚构」
- 没有 DOI 的条目用题名检索，取最相似结果算相似度
- 中文条目单独标记「需知网核验」，附知网/万方/百度学术/Google 一键检索链接
- 结果可导出 CSV、可打印成 PDF

### 2）本地服务（配合插件，推荐）

```bash
cd server
python verify_server.py        # 或双击「启动核验器.cmd」
# 浏览器打开 http://127.0.0.1:8799
```

比单文件多两个能力：

- 页面优先加载 `web/index.html`，插件可以注入桥接脚本；
- 提供 `/report` 一页式核验报告（可直接打印）。

### 3）浏览器插件（中文条目自动化）

`extension/` 是一个 Manifest V3 扩展，Edge / Chrome 通用。

安装：打开 `edge://extensions`（Chrome 是 `chrome://extensions`）→ 打开「开发人员模式」→
「加载解压缩的扩展」→ 选 `extension` 文件夹。

能力：

- 在已登录知网的浏览器里，按「篇名」批量检索题名
- 命中数超过阈值（默认 20）判「疑似虚假」——题名太泛往往意味着文献不存在
- 结果实时回填到 `http://127.0.0.1:8799` 打开的核验器页面，不用复制粘贴
- 撞到安全验证会停下来，手动过验证后点「继续」接着跑

> 前提：浏览器已登录知网（校园网 / 机构账号）。没登录时知网会把深链接重定向到充值页，
> 插件会识别并提示，不会把「购买知网卡」当成检索结果。

## 判定口径

| 等级 | 条件 | 含义 |
|---|---|---|
| A | DOI 能解析 | 属实（高置信） |
| B | 开放库命中且题名高度相似（≥55%） | 疑似属实 |
| C | 未命中 / 中文条目 / 存疑（35%~55%） | 待人工核验 |
| D | DOI 无效 | 虚构（高置信） |
| E | 网络失败 | 查询失败，不计入统计 |

分组统计会按 **有 DOI / 无 DOI / 中文条目 / 查询失败** 分开算，写报告时能明确说清
「哪些结论是硬指标、哪些只能算疑似」。

插件侧判定：

- 结果里有同名题名 → **命中**
- 命中数 > 阈值（默认 20）→ **疑似虚假（命中过多，题名太泛或不存在）**
- 1 ~ 阈值 → **部分命中（需人工看）**
- 0 → **未命中（可能虚构）**

## 设计上的取舍

1. **不做爬虫硬刚反爬**。知网、万方、百度学术都有滑块和风控；插件只做「用你已登录的会话去检索」，
   撞验证就停，交给人。这既是可用性考虑，也避免踩服务条款。
2. **中文不强行判真伪**。Crossref 基本不收录中文期刊，硬判会误伤真实文献，所以中文条目只给
   「需核验」+ 检索链接，最终判断留给人。
3. **没有 DOI 就不宣称结论**。工具只给「疑似 / 存疑」，因为无法证明。
4. **人工合成的那一步保留下来**。判定分四列：工具判定、题录比对、插件判定、人工复核，
   导出的 CSV 能还原整条证据链。

## 目录结构

```
web/index.html          网页版（单文件，无依赖）
server/verify_server.py 本地服务（含 /report 报告页）
server/启动核验器.cmd    Windows 一键启动

```

## 部署到 GitHub Pages

1. 新建仓库，把本目录内容推上去；
2. Settings → Pages → Source 选 `main` 分支、目录选 `/web`；
3. 几分钟后访问 `https://<用户名>.github.io/<仓库名>/`。

Pages 版只有自动核验能力（Crossref），**插件桥接需要本地服务**（`http://127.0.0.1:8799`）。

## 已知限制

- 只查 Crossref；中文命中率低，中文条目必须配合插件或人工；
- 没有 DOI 的条目理论上无法「证明」真伪，工具只给疑似/存疑；
- 浏览器直连 Crossref 有频率限制，条目多时慢一些（每条间隔 0.35 秒）；
- 知网页面结构可能变化，抓不到结果时看页面上「页面诊断」的行数，必要时改选择器；
- 插件需要用户自己先登录知网，登录态不是工具能提供的。
